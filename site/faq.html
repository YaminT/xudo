FAQ

What is the difference between xudo and sudo?

sudo performs the host privilege transition. xudo checks a named-action policy first and sends permitted requests through a broker and gate. This beta always prompts for a password.

Can an AI agent run any command with xudo?

No. The command must match a root-owned rule and pass the deny-list; the host also prompts for a password.

Is this safe? What are the limits?

This is beta software and has not been externally audited. A broad rule can give broad root access; the built-in refusal list is a safety net, not a complete boundary; and other ways to root on the host are outside xudo's control. Agent detection is not a security boundary; the rules are. See SECURITY.md.

Does this work with Claude Code, Codex CLI, Gemini CLI, or Aider?

Yes. Any harness that can run a command can call xudo exec. xudo does not trust a program's name: a harness is verified by the machine, registered once by root. This beta cannot register an agent, so it cannot tell an agent from you and has no passwordless mode. An agent can call xudo exec, and sudo then asks a human for the password. Or it can queue the command with ido queue --root for you to run.

What happens if an agent lies about being an agent?

Nothing changes. Names and environment variables never grant anything. Only a harness root registered, running inside the scope the kernel tracks for it, could ever run commands without a password, and only what its rules allow. Nothing in this release creates such a scope, so lying gains nothing today: every request asks for a password.

How is this different from NOPASSWD: ALL?

No caller can be a registered agent in this release, so every request uses the password path. The package installs only a password-authenticated rule. Actions constrain the executable and arguments, and the gate checks policy again.

Does it work with doas? With sudo-rs?

The package depends on sudo, so package installs use sudo for both xudo install and xudo exec. doas works only with a hand install on a host without sudo; its install probe always reports NOT VERIFIED. Detection and execution prefer sudo. sudo-rs 0.2 is refused at detection; newer sudo-rs, including Ubuntu 26.04's version, works.

Does it phone home?

The default build contains no network code and sends no telemetry. just telemetry runs the strace no-telemetry check, also run by the CI job “no telemetry”.
