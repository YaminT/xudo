FAQ

What is the difference between xudo and sudo?

sudo performs the host privilege transition. xudo checks a named-action policy first and sends permitted requests through a broker and gate. This beta always prompts for a password.

Can an AI agent run any command with xudo?

No. The command must match a root-owned rule and pass the deny-list; the host also prompts for a password.

Is this safe? What are the limits?

It is beta software and has not been externally audited. Agent detection is not a security boundary; the allowlist is. M1 (policy core, explain) done. M2a (backend model) done. M2b done in code and tests (2026-10-30): the broker mints entries, the gate consumes one and runs it as root, xudo exec and xudo install ask the broker, both write one hash-chained audit trail, and the same ruleset behaves the same through sudo, sudo-rs and OpenDoas. M3 is built: out-of-band confirmation via xudo watch is off by default, and every path still requires the password. The broker runs under its real systemd sandbox, and Pasban verifies the audit chain daily. The doas install probe remains NOT VERIFIED. Next: M4 enrollment and the passwordless path, M5 temporary permissions, narrowing and volume controls (pasban's revocation substrate), M6 ergonomics (airead surfaces here), M7 confinement and external audit. confirm_human_path=false by default. just telemetry runs the strace no-telemetry check, also run by the CI job “no telemetry”. See security limits.

Does this work with Claude Code, Codex CLI, Gemini CLI, or Aider?

The policy does not depend on a specific agent, but this beta does not enroll or authenticate agents or provide passwordless execution.

What happens if an agent lies about being an agent?

Agent names and environment variables do not authorize requests. Every caller currently uses the password path.

How is this different from NOPASSWD: ALL?

The package installs only a password-authenticated rule. Actions constrain the executable and arguments, and the gate checks policy again.

Does it work with doas? With sudo-rs?

The package depends on sudo, so package installs use sudo for both xudo install and xudo exec. doas works only with a hand install on a host without sudo; its install probe always reports NOT VERIFIED. Detection and execution prefer sudo. sudo-rs 0.2 is refused at detection; newer sudo-rs, including Ubuntu 26.04's version, works.

Does it phone home?

The default build contains no network code and sends no telemetry. just telemetry runs the strace no-telemetry check, also run by the CI job “no telemetry”.
