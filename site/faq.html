FAQ

What does xudo do?

xudo checks privileged commands against root-owned rules, then uses the host's sudo, sudo-rs, or doas for the privilege transition. The broker and gate both check policy before execution.

Can an AI harness run any command?

No. A command must match a rule and pass the compiled-in deny-list. Passwordless execution requires a verified service harness, an exact rule naming it, and root's explicit opt-in. Otherwise a human path or denial applies.

How is a harness verified?

The shipped enrollment path runs a dedicated account in a root-created systemd service scope. The kernel-attested scope and root-owned registry entry establish the harness. A name or environment value does not. Session start and attach for a harness running as a logged-in user's account are not implemented.

What does ask-human do?

A matching request is written to the root-held broker queue. A separate reviewer uses ido to review it and run it through the password-authenticated path. The requesting harness cannot edit or answer the entry.

Is xudo externally audited?

No. This is beta software and has not been externally audited. The deny-list is defense in depth, broad rules can grant broad access, and xudo cannot remove other host paths to root. See security status and limits.

Does xudo work with OpenDoas?

OpenDoas supports the password-authenticated human path. The optional passwordless agent-path installation is supported only with sudo and sudo-rs.

Does xudo phone home?

The shipped request path does not send requests to an external service. Process hints are bounded, audit-only records. See the repository's security documentation.
