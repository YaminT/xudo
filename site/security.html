Security

Beta. Not externally audited. Do not deploy this where a compromise would matter.

M1 (policy core, explain) done. M2a (backend model) done. M2b done in code and tests (2026-10-30): the broker mints entries, the gate consumes one and runs it as root, xudo exec and xudo install ask the broker, both write one hash-chained audit trail, and the same ruleset behaves the same through sudo, sudo-rs and OpenDoas. M3 is built: out-of-band confirmation via xudo watch is off by default, and every path still requires the password. The broker runs under its real systemd sandbox, and Pasban verifies the audit chain daily. The doas install probe remains NOT VERIFIED. Next: M4 enrollment and the passwordless path, M5 temporary permissions, narrowing and volume controls (pasban's revocation substrate), M6 ergonomics (airead surfaces here), M7 confinement and external audit. confirm_human_path=false by default. just telemetry runs the strace no-telemetry check, also run by the CI job “no telemetry”. The passwordless agent path and Landlock confinement are not in this release. Every caller currently uses the human password path. The package does not install a NOPASSWD rule.

Limits

  • Agent detection is not a security boundary; the allowlist is.
  • The compiled-in deny-list is defense in depth, not a complete boundary.
  • A broad rule can grant broad root access.
  • xudo doctor reports some other paths to root, but cannot prove none exist.
  • The default build has no network code. just telemetry runs the strace no-telemetry check, also run by the CI job “no telemetry”. Stock Ubuntu 26.04 verifies because the install probe runs /usr/bin/gnuid -u when /usr/bin/id is not a regular file. It reports NOT VERIFIED on doas and on a multicall-coreutils system with no regular probe program, such as Alpine. The audit trail records authorization, not outcomes. Pasban runs daily as root to verify the chain and compare journal copies with the file by hash; it detects removed tails, cut-and-continued files, and forged chains the journal never saw. It does not prevent privileged tampering or prove a command completed.

Report a vulnerability

Open a private security advisory on the GitHub repository. Do not open a public issue for an exploitable vulnerability. See SECURITY.md for details.
