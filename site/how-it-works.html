How it works

xudo explain loads policy and reports what it would decide. It executes nothing.

  1. xudo exec sends the requested argv to the root broker over a Unix socket.
  2. The broker identifies its peer from kernel-provided facts, evaluates root-owned rules and the compiled-in deny-list, and records the decision.
  3. For an allowed request, the broker creates a bounded one-use request.
  4. The host's sudo, sudo-rs, or doas invokes the password-authenticated gate.
  5. The gate independently checks policy and the one-use request before executing the validated program.

Errors fail closed. In this beta every caller is unattested, and every privileged request uses the human password path.

ido stores exact argv for human review. It holds no privilege; privileged work still uses xudo's password path.
