Rule format

Native rules are TOML files. Each action fixes one executable and constrains each argument by position. There are no globs.

[[action]]
id = "xudo.svc.status"
tier = "diag-read"
exe = "/usr/bin/systemctl"
args = [
  { name = "no-pager", matcher = { literal = "--no-pager" } },
  { name = "full", matcher = { literal = "--full" } },
  { name = "verb", matcher = { literal = "status" } },
  { name = "unit", matcher = { name = "unit-name" } },
]

This read-only action is from rules/10-diagnostics.toml. The shipped rules do not start or stop a service. To allow that on one host, copy the package's example, /usr/share/xudo/examples/20-services-lifecycle.toml, to /etc/xudo/rules.d/ and list your units in an enumerated one-of. Leave a unit out and the command is refused:

[[action]]
id = "xudo.svc.lifecycle"
tier = "svc-control"
exe = "/usr/bin/systemctl"
args = [
  { name = "no-pager", matcher = { literal = "--no-pager" } },
  { name = "no-ask", matcher = { literal = "--no-ask-password" } },
  { name = "verb", matcher = { one-of = ["start", "stop", "restart", "try-restart", "reload", "reload-or-restart", "try-reload-or-restart"] } },
  { name = "unit", matcher = { one-of = ["example.service", "example-other.service"] } },
]
