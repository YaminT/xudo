Rule format

Root-owned rules are TOML. Each action names one absolute executable and constrains every argument by position with typed matchers.

[[action]]
id = "xudo.svc.status"
tier = "diag-read"
exe = "/usr/bin/systemctl"
args = [
  { name = "no-pager", matcher = { literal = "--no-pager" } },
  { name = "full", matcher = { literal = "--full" } },
  { name = "verb", matcher = { literal = "status" } },
  { name = "unit", matcher = { name = "unit-name" } },
]

Harness rules also name registered labels and select the result. A passwordless allow still needs the operator's explicit agent-path opt-in. An ask-human result goes to the broker's root-held queue for a separate reviewer.

[[action]]
id = "web.restart"
tier = "svc-control"
exe = "/usr/bin/systemctl"
harness = ["codex"]
outcome = "allow"
args = [
  { name = "verb", matcher = { literal = "restart" } },
  { name = "unit", matcher = { one-of = ["web.service"] } },
]

Rule files can also declare deny rules and test cases. xudo check lints the files and runs their tests. See the shipped rules and examples and the xudo-rules(5) manual.

Rule packs

A local pack is one TOML rule file with a [pack] header. xudo rules add FILE prints its effects and a review token without writing. Root installs only after a reviewer runs the command with --reviewed TOKEN; the token is checked against the pack bytes, rules, registry, and waiver choice again. Nothing downloads or updates itself.

path-under is a lexical matcher, not filesystem containment. Use the typed remove-path operation for bounded removal under a root-configured tree.
