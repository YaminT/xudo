xudo

xudo is a Linux privilege broker for operators who want AI coding agents to request narrowly defined privileged commands. It checks commands against root-owned rules and uses the host's privilege backend. This beta runs every request through the human password path.

Beta. Not externally audited. M1 (policy core, explain) done. M2a (backend model) done. M2b done in code and tests (2026-10-30): the broker mints entries, the gate consumes one and runs it as root, xudo exec and xudo install ask the broker, both write one hash-chained audit trail, and the same ruleset behaves the same through sudo, sudo-rs and OpenDoas. M3 is built: out-of-band confirmation via xudo watch is off by default, and every path still requires the password. The broker runs under its real systemd sandbox, and Pasban verifies the audit chain daily. The doas install probe remains NOT VERIFIED. Next: M4 enrollment and the passwordless path, M5 temporary permissions, narrowing and volume controls (pasban's revocation substrate), M6 ergonomics (airead surfaces here), M7 confinement and external audit. confirm_human_path=false by default. just telemetry runs the strace no-telemetry check, also run by the CI job “no telemetry”. The passwordless agent path and Landlock are not in this release. See security status and limits.

Install

No release has been published yet. When one is available, download the .deb, SHA256SUMS, and its .cosign.bundle from the GitHub Release. Replace <ver> with the Debian version, <arch> with amd64 or arm64, and <tag> with the Git tag; for example, <ver> 0.1.0~beta.1 corresponds to <tag> v0.1.0-beta.1.

sha256sum -c SHA256SUMS --ignore-missing
cosign verify-blob --bundle xudo_<ver>_<arch>.deb.cosign.bundle --certificate-identity https://github.com/YaminT/xudo/.github/workflows/release.yml@refs/tags/<tag> --certificate-oidc-issuer https://token.actions.githubusercontent.com xudo_<ver>_<arch>.deb
sudo apt install ./xudo_<ver>_<arch>.deb

xudo has no curl | sh installer because a privileged shell script is difficult to inspect before execution.

Example

From a checkout, --rules ./rules applies to explain. exec ignores --rules; the broker loads root's /etc/xudo/rules.d.

xudo --rules ./rules explain -- /usr/bin/systemctl --no-pager --no-ask-password restart nginx.service
xudo doctor
ido queue -m "restart nginx after review" -- /usr/bin/systemctl restart nginx.service

explain reports a decision without execution. After installing the package, add your user to the xudo group with sudo usermod -aG xudo YOUR_USER, then log out and back in. This is a deliberate privilege grant: group members can invoke the privileged gate. Then run xudo exec -- /usr/bin/systemctl --no-pager --no-ask-password restart nginx.service; it uses the host password prompt and gate.
