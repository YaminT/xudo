xudo

Passwordless for the agent, a prompt for the human

An agent that hits a command needing root either stops unattended work at a sudo prompt or gets NOPASSWD: ALL, a standing root backdoor for every process running as that user. xudo is the middle path: a root-owned allowlist of named actions. Enrolled agent sessions run allowlisted actions without a password; a human invoking xudo is always prompted; a deny-list of catastrophic commands is compiled into the binary and cannot be edited by configuration.

Beta, not externally audited. This build cannot execute anything as root yet: explain, check, list, config, doctor and agentdoc inspect the policy and execute nothing.

[[action]]
id = "xudo.svc.lifecycle"
tier = "svc-control"
exe = "/usr/bin/systemctl"
args = [
  { name = "no-pager", matcher = { literal = "--no-pager" } },
  { name = "verb",
    matcher = { one-of = ["start", "stop", "restart", "reload"] } },
  { name = "unit", matcher = { name = "unit-name" } },
]

# $ xudo --rules ./rules explain -- \
#     /usr/bin/systemctl --no-pager restart nginx.service
# prints the rule that matched, at file:line, the canonical
# argv and the verdict; as JSON when the caller is a model

What it does

  • Named actions, no globs anywhere. A rule fixes the executable and constrains every argument by position. sudoers joins arguments into one string and runs fnmatch, which is how /opt/utils/*.py becomes a root shell.
  • A deny-list in the binary. Catastrophic commands are refused regardless of configuration. It is defence in depth, not the boundary: the set of programs that can become a root shell is not enumerable.
  • Answers a model can read. explain reports which rule matched, where, with what argv and why, in a stable JSON envelope. An exit code and a prose message are the worst interface for a language model.
  • A gate that is identical to CI. just verify: 100% line, region and function coverage with no waivers, zero clippy warnings, cargo deny, miri and three fuzz targets.
