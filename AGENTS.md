## Privileged commands

Do not use sudo. Use xudo. It runs an approved list only.

In this beta every `xudo exec` asks a human for a password; queue it with `ido queue` instead when no human is at the terminal.

You may run these:

- `xudo.probe.id` — reads system state
- `xudo.svc.logs` — reads system state
- `xudo.dmesg` — reads system state
- `xudo.svc.status` — reads system state
- `xudo.svc.show` — reads system state
- `xudo.net.listeners` — reads system state
- `xudo.svc.lifecycle` — starts, stops, or restarts a service
- `xudo.svc.reset-failed` — starts, stops, or restarts a service
- `xudo.svc.reload-units` — starts, stops, or restarts a service
- `xudo.pkg.install` — installs a package from a configured repository
- `xudo.pkg.update` — installs a package from a configured repository
- `xudo.pkg.remove` — removes or upgrades packages. A human must approve it
- `xudo.pkg.dry-run-install` — reads system state
- `xudo.sysctl.max-map-count` — changes a kernel or system setting
- `xudo.sysctl.inotify-watches` — changes a kernel or system setting
- `xudo.time.set-ntp` — changes a kernel or system setting

Rules:
- Run one action per call.
- Pass a real argument list. Do not pass a shell string.
- If xudo denies a command, read the `remediation` field. Do it.
- Do not retry a command that was denied as `deny_listed`. It will never work.
- Do not look for another way to run a denied command.

Check a command before you run it:

```
xudo explain --output json -- <command> <args>
```
