# GTFOBins waivers.
#
# A binary on the GTFOBins list can be turned into a shell, an arbitrary read,
# or an arbitrary write WHEN INVOKED FREELY. Allowlisting one is therefore only
# defensible when the rule constrains it so that the specific technique is
# unreachable. This file is where that argument is written down and reviewed.
#
# Format: <absolute path>|<the GTFOBins technique>|<why the rule neutralises it>
#
# A waiver is not permission to relax the rule later. If a rule that owns a
# waiver here is widened, the waiver's reasoning must be re-checked, because the
# technique it claims is unreachable may no longer be.

/usr/bin/systemctl|Pager escape (`!cmd` via less on a bare `systemctl`), `SYSTEMD_EDITOR` on `edit`, `link`/`enable --now` of a caller-written unit file, and `start`/`stop`/`restart`/`isolate` of a power, sleep, firewall, journal, or debug-shell unit, including `runlevel0.target` and `systemd-poweroff.service`|No shipped action starts, stops, or isolates a unit. `status`, `show`, and `reset-failed` do take a unit the operator did not list: `status` and `show` take `unit-name`, including a `.mount` unit, and `reset-failed` takes `service-unit-name` (a `.service` with no `@` and no backslash). The service-lifecycle rule is an example at `/usr/share/xudo/examples/20-services-lifecycle.toml`; until the operator copies it and replaces the placeholder names, a systemctl lifecycle verb matches nothing. `edit`, `link`, and `enable` are absent from every verb enum and are refused by UnitDefinitionMutation. Every shipped systemctl rule pins `--no-pager`, so less is never spawned, and `SYSTEMD_EDITOR` is absent because the child environment is built from an allowlist. The deny-list is a name list, and the enumeration is the boundary: an alias or a unit that is not named gets past. It is a tripwire on that enumeration: PowerState for power and boot targets, runlevel aliases, and the systemd power and sleep services; SpawnsShell for `debug-shell`; KernelModule for `modprobe@`; DeviceOrFilesystem for `systemd-fsck@`, `systemd-growfs@`, `systemd-makefs@`, and `mdadm*@` (a `.mount` unit is not in this class); SelfModification for `xudod`, `xudo-*`, journald, and rsyslog; SecuritySubsystem for apparmor, auditd, the firewall units, and the time-sync units. A later rule that still uses the generic `unit-name` kind cannot start, stop, or isolate those names. A read-only verb is not refused because of the unit. The journal rules keep `unit-name` because reading a unit's log is the point, and that program is not systemctl.

/usr/sbin/sysctl|Writing a key whose value is a program specification (`kernel.core_pattern=|/tmp/x`, `kernel.modprobe`), and the file-driven forms `-p`, `--load`, `--system`, which apply values from a file the argv does not name|The key is a literal or a closed enum per rule, never a pattern, and each key carries its own integer range. Every code-execution key is in the deny-list's FATAL_SYSCTL_KEYS. The file-driven flags are refused by the ConfigNamedProgram class: `-p` and its alias `-f`, a short cluster containing `p` or `f` (`-qp/path`), the joined forms, and a prefix of `--load` or `--system` (`--l`, `--loa`, `--s`, `--sys`). `--load-extra` is not `--load`, and `-q` alone is not a file load. The values applied by a command this list allows are visible in the argv the matcher checked.

/usr/bin/timedatectl|Pager escape via the systemd pager environment|The only shipped rule takes the fixed verb `set-ntp` with a two-value enum operand and no path, file, or free-form argument. No pager is invoked because no output is paged; `SYSTEMD_PAGER` and `PAGER` are absent from the child environment, which is built from an allowlist rather than inherited.

/usr/bin/ss|Reading a caller-named file via `-F/--filter <file>`, and the pager on long output|The shipped rule has a completely fixed argv (`-tulpnH`) with no caller input reaching it at all, so `-F` is unrepresentable. This is the safest rule shape available and is the reason it was written this way.

/usr/bin/journalctl|Pager escape (`!cmd`, `LESSOPEN`) and the log-mutating flags `--vacuum-*`, `--rotate`, `--setup-keys`|Both journalctl rules pin `--no-pager`. `PAGER`, `LESS`, `LESSOPEN`, `SYSTEMD_PAGER`, and `SYSTEMD_LESS` are absent from the constructed child environment. The remaining positions are a validated unit name, a bounded integer, and closed enums, so no mutating flag can be named.

/usr/bin/apt-get|Maintainer scripts running as root, `-o DPkg::Pre-Invoke::=<program>` which is a /bin/sh injection, and installing a local file or URL|Maintainer-script execution is inherent to this tier and is stated plainly rather than waived: the boundary is that packages come only from configured, root-owned repositories. What the rules do remove is every other route — `-o`, `--option`, `-c`, and `--config-file`, including joined spellings (`-oFoo=bar`, `--option=`, `-c/path`, `--config-file=`), ASCII case variants of those long names (`--Config-File`, `--OPTION`), and a short cluster that contains `c` or `o` (`-yc/path`, `-soDir::...`). `--opt` is not `--option`. Those are refused by the ConfigNamedProgram class. The deb-name matcher rejects `/`, `=`, `:`, `..`, and a leading `-`, so a path, a version pin, an architecture qualifier, and a URL are all unrepresentable.
